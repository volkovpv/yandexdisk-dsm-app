# План: автономный e2e-харнес с само-починкой на VM с DSM

## Цель и принцип
Закрыть класс багов «связанность с DSM» (run-as `sc-yandexdisk`, webman-симлинк → `pwd -P`,
CSRF `SynoToken` на POST, Package Center install), которые проходят герметику и всплывают
только в проде. **Каждый найденный баг конвертируется в дешёвый герметичный тест** — VM
работает детектором, питающим L1, а не постоянным костылём в рантайме. Порядок фаз —
по убыванию риска: сначала гасим главный неизвестный (загрузится ли DSM под WSL2), потом
строим петлю, затем валидируем её на уже известном баге.

## Предусловие (отдельно, до харнеса)
**x86_64-сборка `.spk`** (PR-0). VM x86_64 → нужен amd64-бинарь rclone: смена zip +
2×SHA256, ELF-гейт `e_machine=62` вместо 183, arch-коды в INFO. Реинжиниринга нет —
тот же rclone v1.74.3, официальная сборка `linux-amd64`. Сам харнес и будет валидатором
этого порта. ARM-сборка остаётся байт-в-байт воспроизводимой (default-профиль не меняется).

---

## Фаза 0 — Risk spike: DSM в VM под WSL2
- **Цель:** чистый x86_64 DSM грузится в QEMU/KVM, доступен по `http://IP:5000`.
- **Делать:** проверить nested virt (KVM внутри WSL2); собрать RedPill/ARC-загрузчик под
  целевую версию DSM; `.pat` и загрузчик — **не в git**, тянутся локально/из секрет-стора.
- **Decision gate:** если nested virt не заводится → fallback: облачный bare-metal runner /
  отдельный хост / в крайнем случае контейнер-мок webman (дешевле, но без проверки Package
  Center). Решение фиксируем здесь — дальше не переигрываем.
- **Deliverable:** воспроизводимая «DSM reachable» + документ по источнику `.pat`.

## Фаза 1 — Golden snapshot (детерминизм)
- **Цель:** убрать минуты/интерактив установки из каждого прогона.
- **Делать:** один раз автоматизировать мастер: загрузка `.pat` → создание admin; снять
  qcow2-снапшот «DSM ready». DSM-версия **пиннится под прод** (баги версионно-зависимы).
- **Deliverable:** `provision-vm.sh` (один раз → снапшот), `restore-vm.sh` (секунды, детерминировано).

## Фаза 2 — Deploy + «имитатор человека»
- **Цель:** поставить пакет и пройти пользовательский сценарий.
- **Делать:** установка x86_64 `.spk` через Package Center (API приоритетно, UI — fallback);
  Playwright (fresh context) гоняет UI пакета: добавить папку → вставить токен/«Подключить»
  → «Синхронизировать сейчас».
- **Стабы:** предзасев `rclone.conf` с фейк-токеном (OAuth вне пакета — пропускаем);
  remote `yandexdisk:` → локальный `rclone serve webdav`/контейнер вместо реального Яндекса.
- **Deliverable:** `e2e-run.sh` → `pass/fail` + бандл улик.

## Фаза 3 — Evidence bundle (диагностируемость)
- **Цель:** дать AI сигнал, а не скриншот (причина, по которой 2.x было трудно).
- **Собирать на каждый провал:** HTTP-статус + сырое тело CGI (403-HTML vs JSON), stderr CGI,
  лог webman/synoscgi, `/var/log/packages/*.log` + вывод `synopkg`, реальный uid исполнения CGI.
- **Deliverable:** структурированная папка улик на прогон.

## Фаза 4 — Петля само-починки (в рамках канона)
- **Цикл:** улики → AI пишет **герметичный regression-тест**, падающий по той же причине →
  чинит **только DSM-glue** → полная цепочка гейтов (`build && run-hermetic && check-coverage
  && check-reproducible`) → редеплой в VM → повтор e2e → сходимость/эскалация.
- **Guardrails (жёстко):**
  - **Hard-stop → человек:** security-инвариант, любой контракт CLAUDE.md, версия rclone,
    флаги воспроизводимости.
  - Фикс **не может быть «отключить проверку»**; правки `build.sh`/`test/` — отдельным PR.
  - Цикл **ограничен N итерациями**, обязан сходиться (каждая итерация ↓ число падающих
    ассертов), иначе эскалация с repro-бандлом.
  - Результат — **PR на ревью (фикс + новый тест + улики), не auto-merge.**
- **Рантайм:** Claude headless (`claude -p`/SDK) или Workflow; оркестрация — скрипт, агент внутри.
- **Deliverable:** `e2e-loop.sh`.

## Фаза 5 — Приёмка на известном баге
- **Цель:** доказать, что петле можно доверять.
- **Делать:** откатить в ветке уже исправленный **CSRF/SynoToken**, запустить петлю; ассертить,
  что харнес сам: (1) ловит 403-HTML на POST, (2) пишет герметичный guard, (3) возвращает
  `SynoToken`, (4) проходит гейты.
- **Deliverable:** зелёный прогон петли = acceptance харнеса.

## Фаза 6 — Интеграция в CI как линия L2
- Отдельный workflow: **nightly / pre-release / по лейблу**, не на каждый коммит. L1-герметика
  остаётся главным гейтом. Документация в `docs/`.

## Декомпозиция на PR (по канону)
- **PR-0** — x86_64-сборка `.spk` (предусловие).
- **PR-A** — провижининг + снапшот (`test/e2e/`, без кода пакета).
- **PR-B** — deploy + Playwright + стабы + evidence.
- **PR-C** — петля + guardrails + интеграция в CI.
- **PR-фиксы** — то, что петля найдёт: каждый своим PR (фикс + regression-тест).

## Definition of Done
Петля на чистом снапшоте DSM ставит x86_64-пакет, проходит UI-сценарий против фейк-remote,
на инъецированном известном баге сама воспроизводит → пишет герметичный тест → чинит → зеленит
всю цепочку гейтов, и открывает PR. L1 не ослаблен.

## Риски и fallback
- **Nested virt под WSL2 не заводится** → облачный/bare-metal runner или контейнер-мок webman
  (Фаза 0 gate).
- **Дрейф версии DSM / пересборка загрузчика** → пин версии + ручной апдейт снапшота (редко).
- **Легальность `.pat`** → никогда не коммитим; каждый раннер приносит свой.
- **Стоимость токенов петли** → бюджет на итерации, эскалация вместо thrash.

## Вне scope
Реальный OAuth Яндекса; реальный сетевой Яндекс.Диск; ARM-вариант в VM (тестируется на железе);
авто-мердж фиксов.
