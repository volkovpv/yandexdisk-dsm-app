## 1. Контекст: как качество тестов измеряют эталоны

Оба эталонных проекта — TypeScript/NestJS (гексагональная архитектура) — держат
качество тестов на **двух уровнях**, и это ключевой ориентир.

| Уровень | Инструмент | Порог | Роль |
|---|---|---|---|
| Покрытие | Jest / Istanbul (`--coverage`) | **≥ 80 %** (мягкая цель, сборку не валит) | «Какие строки вообще не исполнялись» |
| Мутационный | **Stryker** (`@stryker-mutator/core` 9.6.1) | **`break: 90`** (жёсткий гейт, валит сборку), `low: 90`, `high: 95` | «Исполнил ли тест код **и проверил** ли результат» |

Конфигурация Stryker в обоих проектах (`stryker.config.json`): мутируются только
слои `src/**/domain/**` и `src/**/application/**`; исключены `*.module.ts`,
`*.dto.ts`, `*.config.ts`, `*.decorator.ts` и весь `infrastructure/`. Прогон —
`coverageAnalysis: perTest`, инкрементальный. Документированная
последовательность проверок: `lint → test:unit → test:mutate → …`, причём
`test:mutate` — тяжёлый шаг, не на каждый коммит.

**Главный вывод.** Настоящий измеритель качества тестов — **мутационное
тестирование**: оно правит исходник (флип оператора, удаление строки) и требует,
чтобы хотя бы один тест **упал**. Если тест исполнил код, но ничего не
заассертил — мутант «выживает», score падает. Покрытие вторично: оно показывает
лишь неисполняемые строки, но не отсутствие проверок.

## 2. Почему «в лоб» перенести нельзя

Пакет — **POSIX-sh** обёртка над `rclone` (`spk/package/common.sh` — 71 строка,
`spk/package/yandex-disk` — 275 строк). Stryker и Jest работают по AST
TypeScript/JS и к shell неприменимы. Зрелого аналога Stryker для POSIX sh не
существует. В среде сейчас **нет ни одного** инструмента покрытия shell
(`kcov`, `bashcov`, `shellspec`, `bats` — все отсутствуют).

Поэтому переносим **идеи**, а не инструменты:
- покрытие shell → `kcov` (один бинарь, оборачивает прогон);
- мутационное тестирование → **свой детерминированный харнесс** поверх
  существующего `test/run-hermetic.sh`.

Обе идеи ложатся на канон проекта «детерминированный результат обеспечивают
гейты, а не модель».

## 3. Аудит: тесты исполняют код, но многое не «прибивают»

Прогон по `spk/package/common.sh` и `spk/package/yandex-disk` выявил ветки и
поведения, которые **исполняются, но не проверяются** (либо не исполняются
вовсе). Это ровно те «survivors», которые выдал бы мутационный прогон. Каждая
строка проверена по коду; ссылки даны как `файл:строка`.

| # | Поведение | Где (исходник) | Статус в тестах | Что переживёт мутацию |
|---|---|---|---|---|
| G1 | `maybe_clean_local` / `clean_thumbs` | `yandex-disk:92` | **0 тестов** (`grep clean_thumbs test/` → пусто) | Код **удаляет файлы**. Можно сломать дефолт (выкл), список имён (`Thumbs.db`/`.DS_Store`), guard `[ -d "$LOCAL" ]` — набор зелёный |
| G2 | Контракт флагов `_bisync` | `yandex-disk:115`, want-список `run-hermetic.sh:116` | частично | t13 закрепляет лишь `--conflict-resolve path1`, `--inplace`, `--max-lock` и 6 exclude-масок. **Не закреплены**: `--check-sync=false`, `--resilient`, `--recover`, `--create-empty-src-dirs`, `--transfers 2`, `--checkers 4`, `--log-format date,time`, `--config`. Удаление/замена любого — мутант выживает |
| G3 | Второй триггер авто-recovery `Must run --resync` | `yandex-disk:177` | поведенчески не исполняется | t04 гоняет только `cannot find prior`. Фраза `Must run --resync` есть лишь в grep по бинарю (`check-rclone-contract.sh:22`) — удали её из обёртки, герметичный набор останется зелёным |
| G4 | `is_configured`, ветка «секция в `rclone.conf` есть, но `dir` пуст» | `yandex-disk:53` | не покрыта | t08 валится уже на первом конъюнкте (пустой conf). Убери `[ -n "$LOCAL" ]` — мутант выживет |
| G5 | `resolve_remote`, «≥ 2 чужих remote, ни один не совпал → не угадывать» | `yandex-disk:35` | не покрыта | t09 проверяет только «ровно 1 чужой remote». Логика «при многих оставить REMOTE как есть» не закреплена |
| G6 | Кэш `rclone_version` (write-miss / read-hit) | `yandex-disk:74` | не покрыт | g01 лишь **удаляет** кэш. Что он записывается при промахе и читается при попадании (без повторного spawn) — не проверено |
| G7 | Роутинг подкоманд `version` / `rclone <args>` / `start\|stop` / usage-fallthrough | `yandex-disk:253`–`274` | **0 тестов** | Любая перестановка веток `case` переживёт набор |
| G8 | `rotate_log`: граница и нечисловой размер | `common.sh:42` | частично | t07 ловит `-gt→-lt`, но не `-gt→-ge` (ровно на лимите) и не ветку `case "$_sz" in *[!0-9]*`  |

Вывод по аудиту: запускать мутационный прогон **до** закрытия этих дыр
бессмысленно — он просто выдаст таблицу выше длинным списком. Сначала ассерты,
потом харнесс как сторож регрессий.

## 4. План улучшений (по убыванию ROI)

### Фаза 0 — закрыть дыры из §3 (РЕАЛИЗОВАНО, без новых инструментов)

Только расширение `test/run-hermetic.sh`: новые сценарии T14+, golden-снимки и
дополненный want-список t13. Не требует зависимостей, поднимает и покрытие, и
будущий mutation score сразу. Все восемь дыр G1–G8 закрыты. Definition of Done:

- G1: три проверки — выключено по умолчанию; при `clean_thumbs=1` удаляются
  `Thumbs.db`/`.DS_Store`; `@eaDir` и прочие имена **не** трогаются; нет
  локальной папки → no-op.
- G2: want-список t13 расширен всеми флагами контракта `_bisync`.
- G3: сценарий с шимом, эмитирующим `Must run --resync` → ожидаем `[auto-recover]`
  и `idle/ok` (по аналогии с t04). Порядок относительно T3/T5 — по правилу в
  шапке `run-hermetic.sh` (триггер-строки в хвосте лога).
- G4: `rclone.conf` с секцией, но пустой `dir` → `not configured`, rc=1.
- G5: два чужих remote, ни один не `yandexdisk` → REMOTE не подменяется.
- G6: probe-проверка записи и чтения `rclone.version`.
- G7: точечные проверки `version`, `rclone <args>` (через `FAKE_ARGS_FILE`),
  `start|stop` (текст «No resident daemon»), неизвестная подкоманда → rc=1 + usage.
- G8: граничный сценарий ротации (размер ровно на лимите → **не** ротируем).

### Фаза 1 — покрытие (РЕАЛИЗОВАНО) — `test/check-coverage.sh`

Исходно планировался `kcov`, но он **не подошёл**: ставится только через
`apt` (а sudo в среде требует пароль), и при этом `kcov` инструментирует лишь
bash — не `dash`, под которым гоняется набор. `bashcov` тянет Ruby. Поэтому
гейт сделан **без внешних зависимостей**, на встроенной трассировке bash, и
закрывает ту же цель — построчное покрытие ядра с порогом:

- `test/check-coverage.sh` (сам POSIX sh) прогоняет `run-hermetic.sh` так, что
  каждый вызов пакетного скрипта исполняется под bash (PATH-шим `sh`→bash), а
  bash через `BASH_XTRACEFD`/`SHELLOPTS=xtrace` пишет по строке на каждую
  исполненную команду в общий лог (`PS4`-маркер `@KC@<файл>@<строка>@KC@`,
  fd 8 — не конфликтует с fd 9 от `flock` в T6).
- Из лога собираются исполненные строки `common.sh` и `yandex-disk`; знаменатель
  («исполнимые» строки) считает awk-классификатор, исключающий то, что xtrace
  не печатает: пустые/комментарии, структурные токены, заголовки функций,
  строки-продолжения (`\`), `}`-с-перенаправлением и метки `case`-веток с пустым
  телом. Печатается процент и **список непокрытых строк** (actionable-отчёт).
- Порог — `YD_COV_MIN` (по умолчанию **90 %** на файл, в духе мутационного
  `break: 90`). Гейт встроен в цепочку: в `POSIX_SH` (линт) и шагом CI после
  `run-hermetic.sh`.

> **Почему под bash безопасно.** POSIX-чистота **уже** форсится `dash -n` +
> `checkbashisms` в `build.sh` — покрытие лишь *измеряется* под bash, и сам набор
> зелёный и под dash (штатный гейт), и под bash (прогон покрытия).

**Результат:** `common.sh` — **100 %** (34/34), `yandex-disk` — **96 %**
(124/129). Непокрытыми осознанно оставлены 5 объективно-негерметичных строк:
fallback-`source` common.sh из установленного target и интерактивная ветка
`read` в `setup` (нужен tty). Замер по ходу Фазы 1 вскрыл два настоящих пробела —
их закрыли тестами **T21** (провал первого `--resync`) и **T22** (подкоманда
`setup`).

### Фаза 2 — мутационный гейт (РЕАЛИЗОВАНО) — `test/mutate.sh`

Герметичный харнесс (сам POSIX sh) — идейный аналог Stryker, ложащийся на канон
«детерминированного результата»:

- **Операторы** (безопасные посимвольные замены, синтаксис не ломают): флипы
  сравнений `-eq/-ne`, `-gt/-le/-ge`, `-lt/-ge/-le`, `-ge/-lt`, `-le/-gt`;
  логические `&&`/`||`; коды возврата `return`/`exit` `0`↔`1`; плюс **точечные**
  мутации строк-КОНТРАКТОВ из `CLAUDE.md` — маркеры лога rclone
  (`Queue copy to Path1/2`, `Copied (replaced existing)`, `Queue delete`),
  exclude-маски, `--conflict-resolve path1`, `--check-sync=false`, триггеры
  recovery (`cannot find prior`, `Must run --resync`). Чисто-комментарные строки
  пропускаются (мутация в комментарии — заведомо эквивалентный мутант).
- **Цикл**: мутант пишется в реальный файл из pristine-копии → прогон
  `run-hermetic.sh` → ожидаем **падение** (killed). Зелёный набор → мутант
  **survived**. `trap` восстанавливает дерево даже при прерывании. Детерминирован
  (порядок файлов и операторов фиксирован — нет случайности/времени).
- **Эквивалентные мутанты** (не меняют поведение: `return`-коды, не потребляемые
  вызывающими; косметика лога; недостижимые без tty ветки) вет­тированы в
  `test/mutate.equiv` и исключены из знаменателя — стандартный приём (аналог
  Stryker «ignored»). Каждая запись с обоснованием и привязкой к строке.
- **Гейт**: `mutation score = killed / (total − эквивалентные)`, порог
  `YD_MUT_MIN` (по умолчанию **90**, по образцу `break: 90`).

**Результат:** первый прогон дал 67 % и вскрыл 3 настоящих пробела — их закрыли
тестами/правкой харнесса: **T23** (`is_configured`: conf без секции при заданном
`dir`), assert в **T22** (без tty `setup` не задаёт интерактивный вопрос) и
точечная мутация `--exclude "Thumbs.db"` (а не текста справки). После триажа 17
эквивалентов **score = 100 %** на рассматриваемых мутантах. Тяжёлый (полный набор
на мутанта, ~2 мин), поэтому вынесен в отдельный неблокирующий workflow
`.github/workflows/mutation.yml` (ночью + по кнопке), а не на каждый push.

## 6. Ограничения канона (обязательно соблюсти при реализации)

Из `CLAUDE.md`:

- Правки `test/`, `build.sh`, `.github/workflows/` — **только отдельным PR**, не
  вместе с кодом, который они проверяют.
- Любой новый sh-скрипт — POSIX sh (`#!/bin/sh`), сразу в `POSIX_SH` в `build.sh`,
  проходит `dash -n` + shellcheck + checkbashisms.
- Новые гейты **не ослабляют** существующие; глушить/обходить проверки запрещено.
- Закрытие дыр **не должно урезать** `--exclude`-список `_bisync` или иные
  security-инварианты — наоборот, цель Фазы 0 их **закрепить**.
- Контракты из `CLAUDE.md` (лог-маркеры rclone, 7-полевой `sync.state`,
  имена вкладок UI/CGI) при добавлении тестов менять нельзя — только фиксировать.
